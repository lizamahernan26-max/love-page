## 4. 改造前的不足与处理方向

1. **没有心里话或后端功能。** 原版没有留言表单、用户登录、持久存储、双人同步、隐私隔离或加密。新增的浏览器本地流程须单独标清边界，不能描述为恢复已有服务器能力。
2. **所有代码挤在单文件。** 姓名和日期散落在页面及脚本中，后期修改容易不一致。按配置、样式、动画、页面交互和心里话拆分即可，不需要换框架。
3. **固定首屏会截断新内容。** `body` 的 `overflow:hidden` 和页面 `100svh` 适合单屏爱心展示，但新增表单后容易无法滚动。保留首屏构图，同时让后续内容及矮屏可滚动。
4. **配置入口尚不存在。** 姓名、日期、音量直接写在源码或依赖媒体默认值。本轮增加可理解的设置，并让标题、姓名和纪念日文案一致更新。
5. **计时只适配当前固定起点。** 原版未处理未来日期或无效日期；加入设置后需要校验，避免负数或无效结果。
6. **动态偏好在加载时读取一次。** 本轮如果调整动画生命周期，可同时兼顾设置变化及页面不可见时的资源使用。

## 5. 新版验收如何避免功能丢失

先比较首页的颜色、层次和主要元素，再逐项检查点心、漂浮文字、计时和音乐。除桌面外，需要检查窄屏、矮横屏、减少动态效果和键盘操作。新心里话流程还需检查默认内存模式、主动保存、取消保存及存储失败时的反馈。

此审计只确认源文件、代码行为和副本哈希，未在本文中宣称浏览器、手机或自动测试已通过。新版运行检查结果由负责实现的交付说明单独记录。
