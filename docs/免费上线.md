# 心网免费上线：GitHub + Render Free + Neon Free

版本 0.5.0，核查日期 2026-10-27。网站仍是原生 HTML/CSS/JavaScript；源码放 GitHub，双人服务由 Node.js 运行，记录保存在外部 PostgreSQL。

## 为什么不能只上传 HTML

GitHub Pages 只运行静态页面，能够展示星空、爱心、百合、音乐和计时，不能执行本项目的登录、身份校验、数据库保存或两人同步。不能把真实心里话写进公开仓库、HTML、JSON、GitHub Issues 或浏览器里的“作者”字段来假装实现私密权限。

完整双人版使用同一个 Render HTTPS 网址提供页面与 API，避免手机浏览器屏蔽跨网站 Cookie。GitHub Pages 地址只能作为展示入口。源码上传、展示页发布、后端部署成功是三个不同状态，须分别核验。

## 免费方案与限制

- Render Web Service 选择 **Free**；不要创建付费磁盘或 Render 的 30 天免费数据库。15 分钟无访问会休眠，再次打开约需一分钟唤醒；每月免费运行时间为工作区共用的 750 小时。
- Neon 选择 **Free**，无需绑卡，目前价格页列出每项目每月 100 CU-hours 和 1 GB 存储。有配额及休眠限制，不承诺无条件永久在线或无限保存。
- 两个平台都不绑定付款方式，不升级套餐，不启用外部保活。使用量达到限额时应暂停使用和导出备份，不能自动转付费。
- 记录正文未实现端到端加密。HTTPS 和数据库 TLS 保护传输，网站权限隔离两位普通用户；维护者及数据库服务方仍有数据库访问能力。

官方依据：[GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[Render Free](https://render.com/docs/free)、[Neon 价格](https://neon.com/pricing)。

## 部署步骤

1. 把经过排除检查的源文件推到自己的 GitHub 仓库。保留根目录 `index.html`、`pianai.mp3`、`assets/`、`styles/`、`js/`，以及后端 `server/`、`scripts/`、`package.json`、`package-lock.json`、`render.yaml`。不要上传 `data/`、真实 `.env`、恢复码、会话、备份或 `node_modules/`。
2. 在 Neon 新建仅供心网使用的 Free 项目。选择与 Render 尽量接近的区域。在连接面板取得 PostgreSQL 连接地址；连接串属于密码，只在平台的环境变量中使用，不发到聊天、不写进 GitHub。
3. Render 控制台选择 **New → Blueprint**，连接刚上传的仓库，使用根目录 `render.yaml`。文件已固定 `plan: free`、新加坡区域、Node 24、启动与健康检查；不创建 Render 数据库或磁盘。
4. 将 Neon 连接串填入 Render 的秘密环境变量 `DATABASE_URL`。`XINWANG_SETUP_KEY` 由 Blueprint 自动生成。不要把它们写到 HTML。若手动新建 Web Service：Build Command 为 `npm ci --omit=dev --ignore-scripts && npm run check:deploy`，Start Command 为 `npm run start:cloud`，Health Check 为 `/healthz`，Node 版本为 `24.19.0`；生成至少 32 字符初始化密钥。
5. Render 提供真实 `https://...onrender.com` 地址后，通过该地址打开心网。程序使用平台提供的 `RENDER_EXTERNAL_URL`，无需猜域名或手填公网 IP。缺少外部数据库、HTTPS 或初始化密钥时会停止启动，不回退到临时 SQLite。
6. 由你在正式网址“账号与绑定”里创建第一个账号，密码自己输入。首个账号需要 Render 环境变量中的初始化密钥；创建后该密钥不能创建第三个账号。
7. 点击“生成她的免登录邀请链接”，私下发送给女朋友。她在自己的常用手机浏览器中点开，再点“进入我们的心网”；无需注册、用户名或密码。链接 24 小时有效且只能使用一次。她应独立保存页面显示的恢复码。

普通邀请码仍保留，供愿意自行设置密码的第二个用户使用。已经建立两个身份后，新的邀请不能覆盖旧身份或使你取得她的私密记录。已有本机账号或记录不会自动上传到云端；可由本人导出自己的记录，经预览后导入，全部先作为私密内容保存。

## 她的免登录身份

浏览器保存 HttpOnly 身份 Cookie，活跃使用时续期；连续 90 天不使用、退出或清除网站数据后，需要恢复码。微信内置浏览器和系统浏览器属于不同的存储空间，建议首次在常用系统浏览器打开并加入书签。

恢复码相当于身份钥匙：只保存摘要，页面仅在进入或重新生成时显示；使用一次即轮换，同时退出所有旧设备。她仍能进入旧手机时可重新生成自己的恢复码。你不能从自己的账号取得她的码。若身份 Cookie 和恢复码都丢失，当前没有无凭据找回方式；导出的文字备份只能在本人另行处理后恢复。

## 验收和备份

- 在两台独立浏览器中确认：共享内容双方可见；各自私密正文、编号和数量不会出现在对方返回数据里；对方不能修改作者记录。
- 检查 `/api/status` 返回 0.5.0 和 `transport: https`；会话 Cookie 为 Secure、HttpOnly、SameSite=Strict；错误 Host、Origin、CSRF 和旧恢复码会被拒绝。
- 重新部署后已有记录仍存在于 Neon；先用测试文字确认，再开始保留真实内容。不能仅凭构建成功或 `/healthz` 就宣称完整双人版已上线。
- 两人分别定期“导出我的记录”，JSON 未加密，应各自妥善保存。维护者备份 PostgreSQL 应使用 Neon 的导出/快照或 `pg_dump`，不能把本机 SQLite 备份命令误当作云数据库备份。
- 免费平台实际可达性仍需两人分别用 Wi-Fi 和移动网络验证；桌面手机尺寸模拟不等于手机实机验证。

## 维护说明

本机仍用 `npm start` 和 SQLite；云端用 `npm run start:cloud` 与 `pg` 8.23.1。新驱动通过锁文件固定。Node 版本固定在 24，未换前端框架。PostgreSQL 表名带 `xinwang_` 前缀；多步写入使用事务和数据库锁，防止两个请求重复消耗邀请或覆盖版本。

`server/cloud.mjs` 仅在 Render 的 HTTPS 入口后使用：公开网关检查规范 Host 和 `X-Forwarded-Proto`，清理转发头，再转交本机回环后端；原有来源和 CSRF 校验保留。不要把此入口直接暴露在任意不可信 TCP 代理后。`/healthz` 仅检查进程，不向数据库发保活查询。

`npm test` 会明确跳过未配置的 PostgreSQL 实测；真实 PostgreSQL 检查需专用本机测试库与 `XINWANG_TEST_PG_URL`，禁止指向生产库。浏览器测试数据与截图均是独立临时数据库的演示内容。
